# 弟子事务权重系统 (Disciple Task Priority System)

> **Status**: Approved
> **Author**: User + Claude
> **Last Updated**: 2026-05-09
> **Implements Pillar**: 门派自动化管理

## Overview

弟子事务权重系统管理弟子的精力分配策略。玩家为每个弟子分配10个权重点到不同事务上，**权重代表精力分配比例**（权重5 = 消耗50%精力），同时也是执行优先级（高权重先执行）。弟子按权重从高到低依次执行事务，每次消耗对应比例的精力，直到精力耗尽或所有加权事务完成。该系统让玩家通过"设置精力分配策略"来规划弟子的发展方向，弟子自动执行策略，玩家只需在关键时刻调整。

## Player Fantasy

玩家作为门派掌门，通过分配权重感受到"规划弟子精力分配"的决策感。权重不只是"先做什么"，而是"花多少精力做什么"——"这个弟子50%精力用于修炼武功"比"这个弟子优先修炼"更具体。设置好权重后，弟子自动按策略分配精力执行事务，玩家有"设置策略后放心放手"的管理感。当门派状态变化时（新设施建成、资源短缺），玩家调整权重策略，体验"关键时刻干预"的决策乐趣。

## Detailed Design

### Core Rules

**权重 = 精力分配比例**（核心设计理念）：

- 每个弟子有 **10个权重点** 可分配
- 权重代表 **精力分配百分比**：权重5 = 消耗50%精力
- 权重总和必须等于 **10点**（意味着100%精力被规划）
- 权重同时也是 **执行优先级**：高权重事务先执行
- 权重为0表示弟子**不分配精力**给该事务（禁止）

**事务类型**：

| 事务 | 目标选择 | 精力消耗公式 | 执行条件 | 效果 |
|------|----------|-------------|----------|------|
| **修炼武功** | 选择目标武功 | 基础10 + 武功级别×2 | 需藏经阁、武功槽位未满 | 学习目标武功 |
| **训练武功** | 选择目标武功 | 固定15 | 需对应练武场、已学武功≥1 | 目标武功经验值增加 |
| **江湖探索** | 选择目标城市 | 20（主城10） | 无设施要求 | 获取目标城市资源、触发事件 |
| **炼制丹药** | 选择目标丹药 | 5 + 药品等级×3 | 需炼丹房、药材足够 | 获得目标丹药 |
| **锻造装备** | 选择目标装备 | 10 + 装备等级×5 | 需兵器坊、木材+金属足够 | 获得目标装备 |
| **休息恢复** | 无需选择 | 0（恢复精力） | 需弟子房空闲房间 | 精力恢复到上限 |

> **注意**：江湖任务不在权重系统内，玩家通过专门的**江湖任务界面**手动选择任务和执行弟子。详见江湖任务界面设计。

**目标选择数据结构**：

```typescript
interface DiscipleTaskConfig {
  // 权重配置
  learnMartial: number      // 修炼武功权重 (0-10)
  trainMartial: number      // 训练武功权重 (0-10)
  explore: number           // 江湖探索权重 (0-10)
  alchemy: number           // 炼制丹药权重 (0-10)
  forge: number             // 锻造装备权重 (0-10)
  rest: number              // 休息恢复权重 (0-10)
  // 总和必须 = 10（江湖任务不参与权重分配）
  
  // 目标选择（权重>0时必须设置）
  targetSkillToLearn?: string    // 修炼目标武功ID（从藏经阁解锁列表选择）
  targetSkillToTrain?: string    // 训练目标武功ID（从已学武功选择）
  targetCity?: string            // 探索目标城市ID（从10城市选择）
  targetMedicine?: string        // 炼制目标丹药ID（从炼丹房解锁列表选择）
  targetEquipment?: string       // 锻造目标装备ID（从兵器坊解锁列表选择）
}
```

**精力分配执行流程**：

当弟子开始执行事务时：
1. 计算当前精力
2. 按权重从高到低遍历事务
3. 对每个权重>0的事务：
   - 计算该事务分配的精力 = 当前精力 × (权重 / 10)
   - 检查条件是否满足（设施、资源、武功槽位等）
   - **条件满足**：执行事务，消耗分配的精力
   - **条件不满足**：跳过该事务，这部分精力保留
4. 继续下一权重事务，直到所有加权事务处理完
5. 如果还有剩余精力且未触发休息：继续从高权重重新循环
6. 精力耗尽或休息权重触发时，进入休息状态

**执行时长机制**：
- 每个事务有等待时长（修炼40秒、训练10秒、探索30秒等）
- 弟子执行事务时需要等待该时长
- 时长结束后扣除精力并完成事务

**权重调整时机**：
- 玩家可在任何时候调整权重
- 调整后**立即生效**（下次精力分配使用新权重）
- 权重调整不消耗任何资源

**预设模板**（一键应用）：

| 模板名称 | 权重配置 | 适用场景 |
|---------|---------|---------|
| 专注修炼 | 修炼5、训练3、休息2、其他0 | 培养武功高手 |
| 资源采集 | 探索5、休息3、其他0 | 快速积累资源 |
| 后勤支援 | 炼丹3、锻造3、探索2、休息2、其他0 | 制作装备药品 |
| 全面发展 | 修炼2、训练2、探索2、炼丹1、锻造1、休息2 | 均衡成长 |

### States and Transitions

**弟子事务状态**：

| 状态 | 说明 | 触发条件 |
|------|------|---------|
| 空闲 | 弟子无当前事务，等待执行 | 精力恢复完成、事务完成 |
| 执行中 | 弟子正在执行某项事务 | 权重分配后开始执行 |
| 休息中 | 弟子在弟子房休息恢复精力 | 精力耗尽、休息权重触发 |

**权重配置状态**：

权重配置是持久化数据，存储在弟子数据中：

```typescript
interface DiscipleWeights {
  learnMartial: number    // 修炼武功权重 (0-10)
  trainMartial: number    // 训练武功权重 (0-10)
  explore: number         // 江湖探索权重 (0-10)
  alchemy: number         // 炼制丹药权重 (0-10)
  forge: number           // 锻造装备权重 (0-10)
  rest: number            // 休息恢复权重 (0-10)
  // 总和必须 = 10（江湖任务不在权重系统内）
}
```

**状态转换**：

- 空闲 → 执行中：按权重分配精力，开始执行最高权重事务
- 执行中 → 执行中：当前事务完成，继续执行下一权重事务
- 执行中 → 休息中：精力耗尽或休息权重触发
- 休息中 → 空闲：精力恢复完成

## Formulas

### 精力分配公式（核心）

```
事务分配精力 = 当前剩余精力 × (权重 / 总权重)

示例：弟子精力100，权重配置 [修炼5, 训练3, 探索2]
执行流程：
1. 修炼分配精力 = 100 × (5/10) = 50精力 → 执行修炼 → 剩余50精力
2. 训练分配精力 = 50 × (3/10) = 15精力 → 执行训练 → 剩余35精力
3. 探索分配精力 = 35 × (2/10) = 7精力 → 执行探索 → 剩余28精力
4. 所有加权事务完成，剩余28精力 → 继续循环（从修炼开始）
```

### 事务执行时长

| 事务 | 执行时长 | 说明 |
|------|----------|------|
| 修炼武功 | 2时辰 | 悟性越高时长越短（时长 = 2时辰 / (1 + 悟性×0.1)） |
| 训练武功 | 0.5时辰 | 固定时长 |
| 江湖探索 | 1.5时辰 | 固定时长 |
| 炼制丹药 | 1时辰 | 固定时长 |
| 锻造装备 | 1.25时辰 | 固定时长 |
| 休息恢复 | 3时辰 | 弟子房等级越高恢复越快 |

### 事务产出公式

各事务的产出详见对应的系统文档：

| 事务 | 产出公式 | 文档 |
|------|---------|------|
| 修炼武功 | 学习新武功，初始经验0% | martial-arts-learning-system.md |
| 训练武功 | 经验增量 = 5% × 悟性系数 × 练武场效率 | martial-arts-learning-system.md |
| 江湖探索 | 资源获得 = 基础量 × 资源等级系数 | jianghu-map-system.md |
| 炼制丹药 | 丹药等级 × 药材消耗 | medicine-system.md |
| 锻造装备 | 装备等级 × 材料消耗 | equipment-system.md |
| 休息恢复 | 恢复精力 = 上限 × (50% + 弟子房等级×10%) | vitality-system.md |

> **江湖任务**：不在权重系统内，玩家通过专门的江湖任务界面手动选择任务和执行弟子。

### 权重调整验证

```
权重调整规则：
1. 新权重总和必须 = 10
2. 每种权重范围 = 0-10
3. 调整不消耗资源
4. 调整后立即生效（下次精力分配使用新权重）
5. 权重为0的事务不会被分配精力（禁止）
```

## Edge Cases

| 边界情况 | 处理方式 |
|---------|----------|
| 权重总和不为10 | 拒绝保存，提示"权重总和必须为10" |
| 权重超过10 | 拒绝保存，提示"单项权重不能超过10" |
| 权重为负数 | 拒绝保存，提示"权重不能为负数" |
| 所有事务权重为0 | 不允许，总和必须=10，至少有一项>0 |
| 高权重事务条件不满足 | 跳过该事务，保留这部分精力，继续下一权重 |
| 分配精力不足以完成事务 | 消耗全部分配精力，部分完成（如修炼进度减半） |
| 精力为0时尝试执行 | 自动进入休息状态 |
| 所有加权事务都不可执行 | 提示"无事可做"，弟子进入空闲状态 |
| 休息权重为0但精力耗尽 | 强制进入休息状态（精力为0必须休息） |
| 设施不存在时的加权事务 | 该事务在过滤阶段被跳过 |
| 资源不足时的加权事务 | 该事务在过滤阶段被跳过 |
| 弟子正在执行事务时调整权重 | 当前事务继续完成，下次精力分配使用新权重 |
| 武功槽位已满时的"修炼武功" | 该事务被跳过，精力保留 |
| 无已学武功时的"训练武功" | 该事务被跳过，精力保留 |
| 等待时长中弟子被中断 | 取消当前事务，扣除精力 = 分配精力 × (已等待时长 / 总时长) |
| 循环执行超过上限（5次） | 强制进入休息状态，防止无限循环（无事务可执行时） |

## Tuning Knobs

| Knob | 默认值 | 安全范围 | 影响什么 | 极端设置后果 |
|------|--------|----------|----------|-------------|
| 权重总数 | 10 | 5-20 | 弟子可分配的策略精细度 | 太少：策略过于粗糙<br>太多：策略过于复杂 |
| 事务类型数量 | 6 | 4-10 | 弟子可做的事情种类（不含江湖任务） | 太少：玩法单调<br>太多：玩家难以管理 |
| 休息权重强制执行 | 是 | 是/否 | 精力为0时的行为 | 否：弟子可能卡死不做事 |
