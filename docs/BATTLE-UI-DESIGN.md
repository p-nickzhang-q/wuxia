## 1. 概述---

## 1. 概述

### 1.1 设计目标

战斗界面是玩家进行回合制卡牌对战的核心交互界面，需要：
- 清晰展示战斗状态（角色、手牌、轻功顺序）
- 流畅的交互体验（选牌、选技能、选目标）
- 支持多人战斗（1v1 和团队战）
- 响应式布局适配不同分辨率

### 1.2 核心设计原则

1. **处理器分离**：UI、布局、输入、AI 各司其职
2. **响应式布局**：使用 anchors + 容器自适应
3. **事件驱动**：通过 Godot 信号系统解耦组件
4. **状态同步**：UI 状态与 GameState 保持一致

---

### 2.3 信号系统

```gdscript
# GameState 发出的信号
signal turn_started(turn_number: int)
signal card_drawn(character_id: String, cards: Array)
signal character_damaged(character_id: String, damage: int)
signal character_shielded(character_id: String, amount: int)
signal passive_triggered(character_id: String, passive_id: String)
signal game_over(player_won: bool)

# UI 组件发出的信号
signal card_selected(card_instance_id: String)
signal skill_selected(skill_id: String)
signal target_selected(target_id: String)
signal action_confirmed()
signal action_cancelled()
signal turn_ended()
```

## 4. 交互流程

### 4.1 基础招式流程

```
1. 玩家点击手牌
   → CardUI.selected = true
   → 进入目标选择模式

2. 系统计算可攻击目标
   → 根据卡牌攻击范围
   → 高亮目标面板

3. 玩家点击目标（或自动选择唯一目标）
   → CharacterPanel.targeted = true

4. 玩家点击确认
   → 执行 useBasicCard()
   → 播放动画
   → 更新 UI
```

### 4.2 武功招式流程

```
1. 玩家点击技能按钮
   → SkillButton.selected = true

2. 玩家点击匹配类型的手牌
   → 检查 requiredCardType
   → 进入目标选择模式

3. 玩家选择目标并确认
   → 执行 useSkill()
   → 播放动画
   → 更新 UI
```

### 4.3 防御卡牌流程

```
1. 玩家点击纯防御卡牌（有护盾无伤害）
   → 自动选择自己为目标
   → 无需目标选择

2. 玩家点击确认
   → 执行动作
```

### 4.4 结束回合流程

```
1. 玩家点击"结束回合"
   → 当前角色轻功清零
   → 检查是否切换行动方
   → 检查是否回合结束
```

### 6.1 动画类型

| 动画 | 触发时机 | 时长 | 实现方式 |
|------|----------|------|----------|
| 卡牌悬停 | pointer_enter/exit | 0.15s | PropertyTweener |
| 卡牌选中 | setSelected(true) | 0.15s | PropertyTweener |
| 抽牌飞入 | CARD_DRAWN 信号 | 0.3s | PropertyTweener 序列 |
| 伤害数字 | CHARACTER_DAMAGED | 0.5s | PropertyTweener + 队列 |
| HP/MP 条 | update() | 0.3s | PropertyTweener |
| 面板震动 | CHARACTER_DAMAGED | 0.3s | PropertyTweener (position) |
| 回合提示 | TURN_STARTED | 0.8s | PropertyTweener (alpha + scale) |

### 6.2 动画工具类

```gdscript
# utils/tween_helper.gd
class_name TweenHelper

static func shake(node: Control, intensity: float, duration: float) -> Tween:
    var original_pos = node.position
    var tween = node.create_tween()
    for i in range(3):
        tween.tween_property(node, "position", original_pos + Vector2(randf_range(-1, 1) * intensity, 0), duration / 6)
        tween.tween_property(node, "position", original_pos, duration / 6)
    return tween

static func fly_in(node: Control, from: Vector2, to: Vector2, duration: float) -> Tween:
    node.position = from
    node.modulate.a = 0
    var tween = node.create_tween()
    tween.parallel().tween_property(node, "position", to, duration)
    tween.parallel().tween_property(node, "modulate:a", 1.0, duration)
    return tween
```

## 10. 注意事项

### 10.1 与 GameState 的同步

UI 组件不直接修改游戏状态，所有状态变更通过 GameState 进行：
- UI 发出信号 → Battle.gd 接收 → 调用 GameState 方法 → GameState 发出变更信号 → UI 更新

### 10.2 性能考虑

- 避免每帧更新 UI，只在状态变更时更新
- 使用对象池管理伤害数字等频繁创建的特效
- 动画使用 PropertyTweener 而非 _process

### 10.3 可访问性

- 所有交互元素支持键盘导航
- 颜色不只是唯一区分方式（配合图标/文字）
- 文字大小可配置
